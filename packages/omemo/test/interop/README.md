Interop tests against the python-omemo reference stack.

vectors.json is generated by scripts/gen_vectors.py using the reference
implementation installed in packages/omemo/.venv (xeddsa, x3dh,
doubleratchet, oldmemo, twomemo). Regenerate with:

    .venv/bin/python scripts/gen_vectors.py

All key material is derived deterministically from SHA-256 of fixed labels,
so the output is stable and safe to commit.

interop.test.ts asserts our implementation produces and consumes the same
bytes as the reference stack for:

- HKDF-SHA256 (RFC 5869 cases), AES-256-CBC, AES-128-GCM
- XEdDSA signatures incl. the smuggled sign bit, X25519, Ed<->Curve
  conversions and the 33 byte legacy key wire encoding
- X3DH shared secret and associated data for both profiles
- Double Ratchet wire ciphertexts, in-order and out-of-order, plus skipped
  message key derivation, for both profiles
- OMEMO protobuf structures and the <encrypted>/<bundle> XML wire format,
  including the legacy Signal-style field numbering (OMEMOMessage
  dh_pub=1 n=2 pn=3 ct=4, OMEMOKeyExchange pk_id=1 ek=2 ik=3 msg=4
  spk_id=6) and the legacy sender-first associated data ordering

scripts/py_verify.py is a one-shot bridge invoked by some tests to have the
reference stack verify our signatures and decrypt our ciphertexts. Tests
that need it are skipped when .venv is absent.

Note: vectors.json was generated with twomemo and xmlschema installed on
top of the base venv (uv pip install --python .venv/bin/python twomemo
xmlschema).
